Join Paths for MCP-OKN

MCP-OKN's get_join_strategy answers from a hand-curated catalog: one stored join per pair, with refusals that often rest on a note about one graph. find_join_paths answers from the identifiers each graph actually holds at its current release, and shows its evidence.

How it plugs into MCP-OKN

1. A companion MCP tool (built)A small MCP server, standard library only, exposing find_join_paths, connections_of and list_graphs. It can run beside MCP-OKN today, or the tool can move into MCP-OKN and replace refusals in get_join_strategy.
2. Refreshed per releaseThe map is recomputed when a graph's release changes; only changed graphs are re-read. With KGF's downloadable hashed key sets, each graph becomes one download and the 31 crosswalks that are too large today become testable.
3. Catalog fixes as pull requestsEach new or wrongly refused connection is drafted as a catalog entry in MCP-OKN's own format, for a maintainer to accept or reject.
4. Measured effect on an agent (research)Same questions, an LLM agent with and without find_join_paths: how many cross-graph questions it answers, how many it wrongly refuses, and at what cost in tool calls and tokens.
